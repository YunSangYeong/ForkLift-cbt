# 지게차운전기능사 필기 CBT

[GitHub Pages 기본 주소](https://YunSangYeong.github.io/ForkLift-cbt/) · 비공식 자체 제작 학습 앱

전기기능사 CBT의 고정 커밋 `b9a682ccff1b460334b78d5bfad9375b7ec4fbb6`의 React·TypeScript·Vite 코드와 MIT 고지를 재사용했습니다. 지게차 데이터는 새로 작성했으며 전기 문제는 포함하지 않습니다. 표준 스킬 v1.2.0 전체는 `.agents/skills/cbt-site-standard/`에 복사하고 루트 `AGENTS.md`에 연결했습니다. 기존 대상 저장소에는 AGENTS.md가 없었습니다.

## 시험 규칙과 앱의 학습용 배분

2026-10-20 [Q-Net 지게차운전기능사 종목정보(7875)](https://www.q-net.or.kr/crf005.do?id=crf00503&jmCd=7875)의 시험정보 하위 응답을 직접 읽었습니다.

- 영역: 지게차 주행, 화물 적재, 운반, 하역, 안전관리.
- 필기: 객관식 4지 택일형 60문항, 60분.
- 합격: 100점 만점에 60점 이상. 안내된 기준은 총점 기준이며 별도 과목별 과락 조건은 제시되지 않습니다.
- 앱은 5개 영역에서 각 12문항을 뽑고 문항당 동일 배점으로 채점합니다. **영역별 12문항과 동일 배점은 학습용 정책**이며 공식 출제 분포·문항별 배점표를 확인한 것은 아닙니다. 표시 점수는 소수 첫째 자리, 판정은 반올림 전 비율로 합니다. 미응답은 오답입니다.
- Q-Net은 출제기준 적용기간을 2025-01-01~2027-12-31로 안내합니다. 세부 보고서의 모든 항목과 각 문항을 대조한 것은 아닙니다. 메인에 기준 연도·자료 버전 선택 UI는 없습니다.

설정은 `src/qualification.ts`, 기계 판독 프로필은 `docs/qualification-profile.json`에 있습니다. [확인한 자료·검증 결과](docs/verification.md)를 참고하세요.

## 기능

실전시험(절대 종료 시각, 답안 변경, 번호 패널, 제출 확인, 자동 제출, 결과·전체 해설·오답 복습), 랜덤 학습(영역 필터, 즉시 채점, 순회 내 중복 방지, 연속 정답), 오답노트, 북마크, 통계, JSON/CSV 로컬 등록·중복 검사·검증 대기·근거 입력 후 승인·내보내기를 제공합니다.

실전에서는 답안 선택 후, 랜덤에서는 채점 후 Space로 다음 문제에 이동합니다. 마지막 실전 문제에서는 제출하지 않습니다. 입력·선택 컨트롤, 네이티브 버튼, 메뉴, 대화상자, 수정키·IME·키 반복은 보호합니다. 비공식 표시는 사이드바·푸터에, 출처와 검수 범위는 해설·문제은행에 둡니다. 상단 상시 안내 배너는 없고 실제 저장 오류 경고는 유지합니다.

## 문제은행: 실제 1,000문항

| 학습 영역 | 개념 | 계산 조건 변형 | 합계 |
| --- | ---: | ---: | ---: |
| 지게차 주행 | 20 | 6유형 × 30조건 = 180 | 200 |
| 화물 적재 | 20 | 6유형 × 30조건 = 180 | 200 |
| 운반 | 20 | 6유형 × 30조건 = 180 | 200 |
| 하역 | 20 | 6유형 × 30조건 = 180 | 200 |
| 안전관리 | 20 | 6유형 × 30조건 = 180 | 200 |
| 전체 | 100 | 30유형 × 30조건 = 900 | 1,000 |

원문 기출 0, 복원 0, 자체 제작 1,000. ID·정규화 본문과 보기 조합 중복 0, 기본 JSON의 내부 검수 완료 1,000, 검증 대기 0. 개인 로컬 등록은 이 수량에 포함하지 않습니다. 수치 변형을 독립 개념 900개 또는 기출로 세지 않습니다. 같은 개념의 관련 문항은 존재하며 의미상 완전히 독립적인 1,000개 지식을 뜻하지 않습니다.

AI 일반 지식으로 작성한 개념 원고와 명시적인 기초 수학·물리 모형입니다. 내부 조건·보기·해설 검토 및 별도 TypeScript 경로의 계산 검증을 수행합니다. **외부 전문가 검수와 공식 세부 출제기준 전수 대조는 미완료**이며, 실제 기출의 유형·난이도·출제 비율을 재현하지 않습니다. 기본 데이터의 90%가 계산 조건 변형이므로 시험 대비 교재를 대체하는 완전한 내용 구성을 뜻하지 않습니다. 실제 지게차 정격·통로 폭·안전거리는 이론 계산으로 결정하지 말고 제조사 하중표와 현장 절차를 따라야 합니다. [문항 작성·검수 범위](docs/question-review.md).

같은 계산 family는 시험당 한 문항을 우선 추출합니다. 기본 은행은 영역별 개념 20개+계산 family 6개로, 12개의 서로 다른 그룹을 추출할 수 있습니다. 부족한 로컬 은행은 고유 ID로 보충합니다. 랜덤 학습은 필터 내 각 문항을 균등하게 순회하므로 계산 변형 비중이 큽니다.

## 개발·검증

Node.js 24.19.0(최소 22.12.0), npm, Python 3(재생성 검사), Chromium을 사용합니다. 서버·DB·로그인·유료 API·추가 비밀값은 없습니다.

```sh
cd /workspace/ForkLift-cbt
npm ci
npm run dev
npm run check
# Linux에 Chromium이 이미 설치된 경우
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
# Playwright 전용 브라우저를 사용하는 경우 먼저:
npx playwright install --with-deps chromium
npm run test:e2e
# 원고와 계산 조건에서 기본 JSON·양식을 결정적으로 재생성:
python3 scripts/generate-bank.py
```

현재 테스트 결과와 한계는 `docs/verification.md`에 기록합니다. 데스크톱 Chromium과 Pixel 7 에뮬레이션은 실기기 검증과 다릅니다. 생성 스크립트는 무작위 시드를 쓰지 않으며 조건 순서, ID, 보기 회전을 고정합니다. `scripts/concepts.tsv`가 개념 원고입니다. 중간에 행을 삽입해 기존 ID를 바꾸지 말고, 확대 시 기존 ID와 학습 참조를 보존해야 합니다.

## 저장과 개인정보

`forklift-cbt:v1` 키에 진행 중 시험·랜덤 세션·최근 응답 5,000개·시험 30회·오답·북마크·로컬 등록을 저장합니다. 통계는 보관된 최근 응답에 대한 집계입니다. 손상 기록은 자동 덮어쓰지 않고 임시 학습으로 전환합니다. 저장 제한·용량 부족은 경고합니다. JSON 백업 내보내기는 있지만 기록 복원 UI는 없습니다. 초기화는 확인 후 사용자 데이터만 지웁니다. 기본 은행은 남습니다.

동일 소유자의 다른 Pages 앱도 같은 origin을 공유하므로 전용 저장 키를 씁니다. 브라우저·기기·origin이 달라지면 기록이 분리됩니다. 기기 시계 변경은 정적 앱 타이머의 한계입니다. 같은 origin iframe은 테스트하며, 다른 origin 블로그의 제3자 저장 제한·시크릿 모드·실기기 동작은 별도 환경에 따라 달라집니다.

## 배포

Vite base는 `/ForkLift-cbt/`, 기본 URL은 `https://YunSangYeong.github.io/ForkLift-cbt/`입니다. `.github/workflows/pages.yml`은 main push 시 단위 테스트→타입 검사·빌드→PC/모바일 브라우저 테스트 성공 후 Pages 아티팩트를 배포합니다. Actions 로그와 정확한 커밋의 결과로 완료를 확인합니다.

GitHub Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 설정해야 합니다. 현재 통합 인증으로 Pages 최초 활성화 API는 403을 반환했습니다. 첫 main 실행의 검증 작업은 성공했으나 배포 작업은 Pages 미활성화(404)로 실패했으며 공개 사이트 배포는 아직 완료되지 않았습니다. 로컬 성공, 원격 push, CI, Pages 게시, 공개 기능 검증은 서로 다른 단계이며 실제 결과는 검증 문서에 따릅니다. 같은 기본 URL이므로 이후 블로그 iframe 주소를 매번 바꿀 필요는 없습니다.
